Attacking Symmetric Encryption
Cryptanalytic Attacks (cryptanalysis)

⚫ Rely on:
⚫ Nature of the algorithm
⚫ Some knowledge of the general characteristics of the plaintext
⚫ Some sample plaintext-ciphertext pairs

⚫ Exploits the characteristics of the algorithm to attempt to
deduce a specific plaintext or the key being used
⚫ If successful all future and past messages encrypted with that key

are compromised

Attacking Symmetric Encryption
Brute-Force Attacks

⚫ Try all possible keys on some ciphertext until an intelligible
translation into plaintext is obtained
⚫ On average half of all possible keys must be tried to achieve

success

Data Encryption Standard (DES)
• Until recently was the most widely used encryption
scheme

• Referred to as the Data Encryption Algorithm (DEA)
• Uses 64 bit plaintext block and 56 bit key to produce a 64 bit ciphertext
block

• Strength concerns:
• Concerns about the algorithm itself
• DES is the most studied encryption algorithm in existence
• Concerns about the use of a 56-bit key
• The speed of commercial off-the-shelf processors makes this key length
woefully inadequate

Block & Stream Ciphers
Block Cipher
• Processes the input one block of elements at a time
• Produces an output block for each input block
• Can reuse keys
• More common

Stream Cipher
• Processes the input elements continuously
• Produces output one element at a time
• Primary advantage is that they are almost always faster and use far
less code
• Encrypts plaintext one byte at a time
• Pseudorandom stream is one that is unpredictable without
knowledge of the input key

Message authentication
• Without confidentiality
o The message is authenticated but not encrypted
o A message tag (authentication tag) is produced and added to the message

• With confidentiality
o The message is authenticated and encrypted
o The message and the auth tag are encrypted

• Typically message authentication is provided as a separate
function from message encryption

Message Authentication Without
Confidentiality
• Situations in which message authentication without
confidentiality may be preferable include:
o Applications in which the same message is broadcast to a number of
destinations
o An exchange in which one side has a heavy load and cannot afford
the time to decrypt all incoming messages
o Authentication of a computer program in plaintext is an attractive
service

• Thus, there is a place for both authentication and encryption
in meeting security requirements

MAC: Assumtpion and Assurance
• Assumption:
o Only the receiver and the sender know the identity of the secret key

• Receiver’s Assurance (if the calculated code matches)
o the message has not been altered. If an attacker alters the message but does not alter the code,
then the receiver’s calculation of the code will differ from the received code. Because the
assumption, the attacker cannot alter the code
o the message is from the alleged sender. Because the assumption, no one else knows the secret
key, no one else could prepare a message with a proper code
o If the message includes a sequence number (such as is used with X.25, HDLC, and TCP), then the
receiver can be assured of the proper sequence, because an attacker cannot successfully alter the
sequence number

Properties of a secure hash function H

Strong Hash Function

Weak Hash Function

1. Can be applied to a block of data of any size
2. Produces a fixed-length output
3. H(x) is relatively easy to compute for any given x, making both
hardware and software implementations practical
4. Is One-way or preimage resistant
o

For any given code h, it is computationally infeasible to find x such that
H(x)=h

5. Is Second preimage of Weak Collision resistant
o

For any given block x, it is computationally infeasible to find y ≠ x with
H(y)=H(x).

6. Is strong collision resistant
o

It is computationally infeasible to find any pair (x, y) such that H(x) = H(y).

One-way / preimage resistant
• If is easy to find x=H-1(h) a schema like Message Auth with secret value
can be broken as follow
• The attacker
o can observe or intercept a transmission
o obtains the message M and the hash code MD M = H(K || M || K)
o Inverts the hash function K || M || K = H-1(MDM)
o Easy to compute K because it knows M

Weak collision / second preimage resistant
• This prevents forgery when an encrypted hash code is used
o E.g. Message Auth with Private or Public Encryption

• If the hash is not weak collision resistant the attacker can

1. observe or intercept a message plus its encrypted hash code
2. generate an unencrypted hash code from the message
3. generate an alternate message with the same hash code

Strong collision resistant
• It protects against the following kind of attacks

1. Bob sends Alice a message to pay a small amount of money
2. Alice signs the document (acknowledge the message)
3. Bob finds two messages with the same hash, one of which requires
Alice to pay a small amount and one that requires a large
payment.
4. Alice signed the first message and Bob is then able to claim that
the second message is authentic

Asymmetric Encryption Algorithms
• RSA (Rivest, Shamir, Adleman), 1977
o Most widely accepted and implemented approach to public-key encryption
o Block cipher in which the plaintext and ciphertext are integers between 0 and n-1 for some n

• Diffie-Hellman key exchange algorithm 1976
o Enables two users to generate a shared secret that can be used as a secret key for subsequent
symmetric encryption of messages
o Limited to the exchange of the keys

• Digital Signature Standard (DSS)
o Provides only a digital signature function with SHA-1
o Cannot be used for encryption or key exchange

• Elliptic curve cryptography (ECC)
o Security like RSA, but with much smaller keys

Requirements public key cryptography [Diffie
and Helman 1976]
• Computationally easy for a party B to generate PUB, PRB
• Computationally easy for a sender A knowing M and PUB to generate C=E(PUB,M)
• Computationally easy for the receiver to decrypt: M=D(PRB,C)=(PRB, E(PUB,M))
• Computational infeasible for an opponent knowing PUB to determine PRB
• Computational infeasible for an opponent knowing PUB and C to recover M
• Both PR and PU can be used for encryption/decryption (useful but not necessary)
• M= D[PUB,E(PRB,M)] = D[PRB,E(PUB,M)]
